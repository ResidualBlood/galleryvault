# 下载管理

> 中文 · [English](Downloads-EN) | 属于 [使用指南](Usage) 系列

下载队列、重试，以及 ExHentai 官方 zip 归档通道。

## 下载页（`#/downloads`）

下载页管理正在排队、下载中以及历史任务，提供配额监控、状态筛选与批量操作。

### 入队方式与画质

顶部「添加下载」面板支持多行 URL 或 `gid/token` 批量入队。

| 入队方式 | 输入格式 | 画质决定规则 | 处理行为与限制 |
| :--- | :--- | :--- | :--- |
| **逐页下载** | 多行 URL 或 `gid/token` | 显式指定原图或重采样；未指定时继承系统全局画质设置（缺省重采样） | 逐页拉取 H@H 节点图片。若原画廊被标记替换，自动改下新版本（最多 5 跳）；详情页「给这本下原图」不跟踪新版本；404 或已删除画廊直接终止重试并提示 |
| **归档下载** | 多行 URL 或 `gid/token` | 在弹出的费用预览窗口中选择原图或重采样 | 走 ExHentai 官方打包通道，通过单连接流式下载 zip 压缩包；需消耗账户 GP |

任务标题根据设置中的「标题显示」选项解析为日文或英文标题。

### 状态、徽标与任务操作

任务列表每 2 秒自动刷新，支持按状态筛选；空闲刷新只更新变化的行，不整表重绘。

| 任务状态 | 状态徽标 | 进度显示 | 可用操作 | 行为边界 |
| :--- | :--- | :--- | :--- | :--- |
| **等待中 (pending)** | 逐页 · 原图/重采样<br>归档 · 原图/重采样 | 排队等待 | 取消 | 取消后后台工作单元不写入磁盘 |
| **下载中 (downloading)** | 逐页 · 原图/重采样<br>归档 · 原图/重采样<br>回退逐页 | 实时进度条（当前页/总页数、百分比、速度与预计剩余时间） | 暂停（全局）、取消 | 全局暂停后不再认领新页面，当前已开始下载的页面会继续完成；取消后先停止全部页面写入，再清理 `.gv-<gid>` 临时目录并回收占用统计 |
| **成功 (success)** | 对应方式徽标（进冷库标注归档 ok / pending / fail） | 100% | 重试、清除记录 | 清除成功记录仅清理任务列表中的记录，不删除已经入库的画廊文件；重试会重新入队 |
| **失败 (failed)** | 对应方式徽标 | 停留在失败进度 | 重试（单项或勾选批量） | 仅补下缺失或失败页面，已写入页跳过；清空退避计数并立即发起重试 |
| **已取消 (cancelled)** | 对应方式徽标 | 停留在取消进度 | 重试（单项或勾选批量） | 重新激活任务并继续下载未完成页面 |

工具栏「重试所有任务」会清除所有等待中、失败与已取消任务的退避状态并立即重新排队。「清除全部成功」在弹出确认框提示条数后，移除全部成功任务记录。批量与危险操作在请求期间禁用触发按钮，防止重复提交。

### 运行控制与风控限制

- **全局暂停**：遇到 302 临时风控验证（remoteapi.php 挑战）时系统自动触发全局暂停。网页暂停按钮与 Telegram `/pause` 指令共用同一开关。暂停生效后停止领取新页面与目录扫描，已在传输中的单页继续完成，容器重启后保持暂停状态。每个任务对 302 挑战使用独立计数，不消耗普通重试次数；达到上限（默认 5 次，环境变量 `GV_MAX_CHALLENGE_PAUSES`）后该任务标记失败并保留剩余重试预算，可手动重试。
- **配额监控**：页面顶部展示缓存的 GP 余额与图片配额（Image Limit，约 30 分钟刷新一次）。配额消耗达到约 80% 时顶栏显示黄色告警横幅，建议暂停下载以避免触发 509。

### 重试机制与完整性校验

- **缺页补全**：重试时仅补下缺失或失败的页面，已经写入磁盘并校验通过的页面直接跳过。
- **图片完整性校验**：文件写入磁盘时校验文件头部标识，支持 JPEG、PNG、WebP 以及 GIF 动图魔数 `b"GIF8"`，拦截 HTML 错误页或伪装损坏文件。
- **节点切换**：遇到单页传输失败或慢节点时，携带失败节点标识请求调度接口切换至下一节点；接口未返回标识时解析页面并更新任务状态后更换节点。
- **指数退避与 429/509 限流退避**：网络瞬时错误按照 30 秒、2 分钟、8 分钟、30 分钟、1 小时至最长 6 小时进行指数退避重试，累计达到 10 次后标记为失败。HTTP 429/509 统一归类为配额限流错误，客户端记录服务端 `Retry-After`（缺省 60 秒），下载任务按指数退避重新排队，不再作为单页瞬时错误立即重试。失败任务不会自动重新扫描复活，需在下载页手动「重试」或「重试所有任务」恢复（会清零退避计数）。

### 任务完成与通知

- **即时入库**：下载完成后，画廊记录、图片页面和标签直接写入数据库并按需生成封面缩略图，无需执行全量扫描；存储签名与文件扫描器保持一致，后续手动执行全库扫描会自动跳过。若全库扫描正在进行，下载入库会延后到扫描结束后自动处理，不会丢失。
- **Telegram 通知**：配置 Telegram Bot 后，系统在下载完成、下载失败、改下新版本或遭遇 404 删除时推送通知。通知默认采用汇总模式发送，支持在系统设置中调整为即时发送、仅失败发送或关闭通知。

## 归档下载（ExHentai archive）

ExHentai 官方归档通道由服务器将画廊打包为单个 zip 文件，客户端通过单连接流式下载，适合大画廊批量获取。

### 触发入口

- **收藏夹与更新画廊**：在收藏夹（`#/favorites/<favcat>`）或更新画廊（`#/updates`）工具栏点击「归档下载所选」或「以归档形式更新选中」。
- **定时自动归档**：在系统设置中开启「定时扫描大画廊走归档下载」并设置页数阈值。收藏夹自动巡检时，页数超过阈值的画廊走归档通道（使用设置指定的归档画质），未超过阈值的画廊走逐页下载。阈值设为 0 时所有画廊均走归档通道。

### 费用预览

发起归档下载时，界面首先弹出只读费用预览窗口，不预先扣除 GP：
- 顶部展示当前账户可用 GP 余额；
- 列表展示每本画廊的原图与重采样预估费用及文件大小；
- 官方未提供对应画质档位时显示红色缺档提示。

### 确认入队

在费用预览窗口选定画质档位（原图或重采样）并确认后，任务加入下载队列：
- 原图档位获取完整原始分辨率，重采样档位获取服务器单级重采样版本；
- 归档任务与逐页任务共用下载队列；归档 zip 传输的并发固定为 2 路，与 `download_concurrency`（修改后立即生效）相互独立；
- 若同一画廊已有逐页或归档任务排队中，重复添加会提示跳过。

### 断点续传

归档下载支持 HTTP Range 断点续传：
- 任务分配的画质与 zip 下载链接持久化保存在画廊目录的临时元数据中；
- 下载中断或手动重试时直接复用已有链接进行断点续传，不重复向服务器申请打包，不重复扣除 GP；
- 传输全程受低速看门狗保护：预热期（默认 30 秒）后平均速率低于设定下限（默认 10KB/s）即判定为限速并中止，可重试续传。

### 重新打包

若已下载的 zip 压缩包损坏或校验失败，系统会删除损坏的本地文件并重新发起打包请求，此时会重新申请下载链接。
若在两次尝试之间改动了任务画质（例如重采样改为原图），缓存的 zip 链接会被丢弃并重新申请对应档位的归档，可能再次消耗 GP。

### 逐页回退

当归档通道无法提供服务（所选画质不存在、账户 GP 余额不足或归档文件持续损坏）时：
- **开启降级（默认）**：自动降级为逐页下载模式，不扣除 GP，转走 H@H 节点下载。任务状态标记为回退逐页，任务列表显示「回退逐页」徽标。
- **关闭降级**：若在设置中关闭「归档不可用降级为逐页下载」，归档失败后任务直接标记为失败，不自动转为逐页下载，且不消耗自动重试次数。

### 完成入库

归档 zip 包下载完成后，执行与逐页下载一致的收尾流程：写入 `.ehviewer` 与 `.galleryvault.json` 元数据、触发通知推送、写入数据库即时入库；若属于更新画廊任务，入库成功后删除旧版本文件。
