# 库维护

> 中文 · [English](Manage-EN) | 属于 [使用指南](Usage) 系列

顶栏「管理」落到 `#/recycle`。页内 tab：**回收站**、**重复副本**、**收藏夹重复**、**跨 GID 重复**、**缺页体检**、**冷库归档**。日志在顶栏「更多 → 日志」（`#/logs`）。

## 重复副本与查重（`#/duplicates`）

管理页三个查重标签使用独立 hash（无 `?tab=` 参数）：

### 重复副本（`#/duplicates`）

同一画廊（同一 GID）出现在多个扫描根目录时（如下载目录、CBZ 归档或手动复制），系统根据设置项 `duplicate_policy` 自动保留一份，其余副本记录在此标签页。

| 策略值 (`duplicate_policy`) | 保留规则 |
| :--- | :--- |
| `keep_first`（默认） | 优先保留已入库的副本 |
| `prefer_more_pages` | 优先保留页数更多的副本 |
| `prefer_newer` | 优先保留发布时间更新的副本 |
| `prefer_larger` | 优先保留文件体积更大的副本 |
| `prefer_smaller` | 优先保留文件体积更小的副本 |
| `manual` | 全部人工决定，不自动保留 |

- **扫描**：点击工具栏「扫描库」重新扫库并刷新列表。若处于全局暂停状态，则提示暂停且不启动扫描。
- **选择与展示**：每组显示缩略图、标签、页数、大小与发布时间，以「当前保留」徽标指示当前索引指向。可通过「全部 / 待处理 / 已忽略」筛选状态。
- **执行**：
  - **保留此副本**：将当前索引指向该副本。
  - **保留并删除其他副本**：保留当前项并删除其余副本文件。删除前使用 `Path.resolve()` 校验绝对路径严格落在扫描根目录内，防范路径遍历；任一路径校验失败或处于只读状态则拒绝删除。若部分副本删除失败，该组仍保留在列表中，并在响应的 `failed_paths` 中列出未删掉的路径。
- **忽略与恢复**：点击「忽略该组」隐藏当前组；可在状态筛选中选择「已忽略」恢复查看。

### 收藏夹重复（`#/duplicates/favorites`）

针对收藏夹中同一作品的不同重传版本分组（归一化标题 + 画师）。

- **操作**：支持批量取消收藏、取消收藏并删除本地画廊、或忽略该组。已忽略项可在 `#/favorites/ignored` 查看与恢复。
- **注**：旧路由 `#/favorites/manage` 自动重定向至本页。

### 跨GID重复（`#/duplicates/cross-gid`）

跨不同 GID 聚合本地已入库画廊与云端未入库收藏，识别同源重传（汉化、重传、无修等）：

- **聚类打分机制**：算法剥离同人展会前缀（如 `(C100)`、`(COMIC1☆15)`）、社团汉化组标签（如 `[某某汉化组]`）以及版本后缀（如 `[DL版]`、`[中国翻訳]`、`[Digital]`），提取规范化核心标题与 `artist` 画师命名空间，结合编辑距离与相似度加权打分进行同源作品聚类。
- **本地与云端对照**：同组并排显示本地已入库副本（画廊 ID、磁盘路径、页数、画质）与收藏夹中未入库的云端画廊（封面、发布日期）。
- **操作与重算**：支持批量取消多余云端收藏、删除本地多余副本，或点击「忽略该组」（后续扫库不再列出）。聚类在扫库完成后于后台计算并缓存，点击「刷新」重新计算。

## 回收站（`#/recycle`）

- 顶栏「管理」入口默认落地点（直接访问 `#/recycle` 仍可用）。两个分页：**用户删除**（库页删除且不删盘）与 **扫描失踪**（扫描时目录里找不到）。
- **恢复**：勾选后恢复重新出现在库中（只恢复「用户删除」；扫描失踪项不会恢复至资料库）。
- **彻底删除**：确认是否删除磁盘文件。勾选删盘时先标进回收站，磁盘全部删除成功后才从索引移除；删盘失败则留在回收站。选择不删文件时响应在 `orphan_paths` 中列出失去索引的磁盘副本，并记录 warning 日志，便于手工接管。任一副本路径不在扫描根白名单内则整本跳过，不删其余合法文件；删除目标就是扫描根目录本身时同样拒绝。
- **语义保护**：回收站内的画廊不会被判定为「新版已在库」而触发旧版本清理。清空历史（`/api/history`）与重置阅读进度（`/api/galleries/progress`）必须带 `?confirm=true`，前端会弹出确认提示。删除文件与清理重复副本时，绝对路径必须落在扫描根或归档根（`archive_roots`、`archive_root`、`cold_storage_root`）内；筛选删除在无筛选条件时拒绝执行。

## 冷库归档（`#/archive`）

- 管理页标签 `#/archive`。需要先在「设置 → 资料库」填写 `archive_roots`（容器内路径，每行一个），并在 Compose 中挂载对应卷。存储配置与路径规则详见 [部署指南 → 冷热分层存储、多盘挂载与归档规则](Deployment#冷热分层存储多盘挂载与归档规则)。
- **开始归档**：将已入库画廊打包为 CBZ，按各归档根剩余空间选盘。打包路径为 `{cold}/cbz/{hh}/{ii}/{gid}-{DB 英文标题}.cbz`。`.galleryvault.json` 与 `ComicInfo.xml` 写入包内。单卷上限 500 页且 2GiB，超限打包为 `{cold}/dir/{hh}/{ii}/{gid}/` 目录。执行中可点击「取消归档」。
- **清理已归档源目录**：冷端生成完好 CBZ 后，删除热目录对应的解压源文件夹。任务会自动跳过 `pending` 与 `downloading` 状态任务。设置页存储面板提供相同操作入口，执行进度在 `#/logs` 查看。
- 未配置归档根或未点击开始时，系统不会自动打包或删除源文件。

## 缺页体检（`#/integrity`）

- 访问 `#/integrity`。列出已记录页数与落盘页数不一致、或存在损坏图片的画廊（未记录页数除外）。进入页面不会自动触发全盘扫描。
- **扫描缺页与坏图**（`POST /api/galleries/integrity/scan`）：点击工具栏「扫描」触发后台巡检任务，采用 2 并发限速校验落盘文件：
  - **魔数与命名校验**：读取文件头最多 20 字节校验 JPEG (`FF D8 FF`)、PNG (`89 50 4E 47`)、GIF (`47 49 46 38`) 与 WebP (`RIFF....WEBP`) 标志，并校验 4 位 / 8 位补零命名规范，识别网络中断残图、403/503 HTML 错误页及乱序错页；
  - **执行状态**：扫描结束将耗时、扫描文件总数及损坏画廊数量写入任务历史日志（`#/logs`）；全局暂停时页面显示暂停提示且不启动扫描。
- **差量补页修复**：
  - 扫描完成后，列表中标红高亮异常画廊，显示记录总页数与实际磁盘有效图片数；
  - 点击卡片上的「修复」或工具栏「全选并修复」；
  - 修复只重新下载缺失页与校验失败的页，完整页面不重复下载，画质沿用原档位（原图或重采样）。详细日志在 `#/logs` 查看。

## 日志页（`#/logs`）

分为两个标签页：

1. **后台任务活动（Task Activity）**：展示后台任务（包括库扫描、标签同步、缩略图生成、收藏元数据同步、查重扫描、画廊更新检测，以及孤儿缩略图清理、缩略图周期播种、Cookie 健康巡检与存储容量校准等静默巡检维护任务）：
   - **进行中**：每行 = 开始时间 · 任务名 · `进行中 · done/total` · 进度条 · 描述 · **取消**按钮；多任务可并排多行。
   - **已完成**：开始时间 · 任务名 · 状态徽标（成功/失败/已取消）· 描述与原因 · **耗时** · 完成时间；已完成任务不再显示进度条。
   - **静默任务与自动化观测**：除了前台显式触发的操作外，系统统一追踪并暴露各类定期静默巡检任务（如孤儿缩略图定时清理、定时补充缺失缩略图、Cookie 探活以及磁盘用量校准），无论是正在运行还是执行完毕，均能在活动面板清晰查验其耗时、执行明细与健康状态。失败的下载任务不会自动复活，恢复入口是下载页的手动重试。
2. **系统运行时日志（System Logs）**：查看后端服务运行时的实时诊断日志（内存环形缓冲区，启动时只回填日志文件尾部若干行，不会整读历史大文件）：
   - **动态调级**：可在线切换全局日志级别（`DEBUG` / `INFO` / `WARNING` / `ERROR`），无需重启容器；
   - **实时筛选与搜索**：支持按最低日志级别（`INFO+` / `WARN+` / `ERROR+`）筛选与文本关键字快速检索；搜索或级别变更只发起一次请求，过期响应不会覆盖当前结果；
   - **异常堆栈与上下文**：错误自动展示可展开的 Traceback 堆栈，并带请求 ID、Worker 协程上下文（`gid` / `task_id`）与敏感凭据自动脱敏（`ipb_*` Cookie、Telegram Token、密钥等安全遮蔽）；
   - **导出日志**：工具栏「导出日志」下载 `galleryvault.log`（环形缓冲 + 落盘轮转文件，`GET /api/system/logs/download`，仅当前日志根内文件），便于把诊断归档发出；
   - **噪音过滤**：httpx 成功请求（2xx/3xx，含 Telegram `getUpdates` 30s 长轮询）不进入本页；4xx/5xx 与业务 WARNING/ERROR（如 bot 轮询失败、通知发送失败）仍保留。

页面每 2~3 秒自动轮询刷新。设置里的「立即同步标签 / 立即生成 / 立即更新翻译」触发后也会在此留痕。

> 提示：跨容器看 Nginx / 后端 / 数据库原始输出，用 `docker compose logs -f` 或 `docker logs galleryvault-backend --since 5m`。仓库默认 compose 不含 Dozzle。
