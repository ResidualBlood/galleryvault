## 一、安装与部署排错

### 1. 跨网段或反代访问时，提交操作报「Cross-origin request rejected」？
- **原因**：系统的 CSRF 防护机制校验客户端来源与服务端 Host。反代剥掉 `Origin`、客户端 `Origin: null`（如沙箱 iframe），或请求带有会话 Cookie 却无有效 CSRF 凭据时，变更请求会被拒绝（HTTP 403）。
- **处理**：确保反向代理正确透传 Host 并保留 `Origin` 请求头（例如 Nginx 配置 `proxy_set_header Host $http_host;`）。若客户端位于私网反代网段后，在 `docker-compose.yml` 中设置 `TRUSTED_PROXIES` 白名单。
- **详情**：参见 **[部署指南 → 安全加固](Deployment#反向代理最佳实践)**。

### 2. 如何修改外部访问端口或绑定自定义域名？
- **原因与场景**：默认端口被占用，或需要绑定独立域名与启用 HTTPS。
- **处理**：在 `docker-compose.yml` 中调整 `galleryvault-frontend` 服务的宿主端口映射（例如 `"8888:80"`）。绑定独立域名与 HTTPS 时，在宿主机配置 Nginx 或 Caddy 终结 TLS 并反代至前端容器端口。
- **详情**：参见 **[部署指南 → Compose 服务定义与环境配置](Deployment#1-compose-服务定义与环境配置)**。

### 3. 数据库容器报错 `Operation not permitted` 无法启动？
- **原因**：PostgreSQL 官方容器固定运行在容器内 `postgres` 用户（UID 999）。宿主机 `./db-data` 目录若被改属主给其他用户会导致权限不足。
- **处理**：不要整体更改属主。若已误改，在宿主机执行 `chown -R 999:999 ./db-data` 恢复权限。
- **详情**：参见 **[部署指南 → 权限映射规范 (PUID / PGID)](Deployment#权限映射规范-puid--pgid)**。

### 4. 扫描 7z 压缩包是否会将全部图片解压到磁盘？
- **原因与机制**：扫描只读取包内文件目录并索引图片成员，不会整包解压到库目录；阅读单页时按需在内存中解压对应图片。
- **限制**：单页未压缩大小上限为 **128MB**，超出限制则拒绝读取该页（HTTP 404）。`.cbr` / `.rar` 格式需宿主机安装 `unrar` 或 libarchive，否则扫库无法解析。
- **详情**：格式支持与解压限制参见 **[客户端格式与元数据规范 → 压缩归档格式支持矩阵](Compatibility#1-压缩归档格式支持矩阵)**。

### 5. 升级到 PostgreSQL 18 后数据库容器起不来？
- **原因**：`postgres:18-alpine` 镜像将数据存放在 `/var/lib/postgresql` 下的版本子目录中。若继续挂载旧路径 `/var/lib/postgresql/data` 或设置了 `PGDATA`，目录非空检查会导致容器退出。
- **处理**：直接将宿主机 `./db-data` 挂载到 `/var/lib/postgresql`，不要设置 `PGDATA`。新安装直接执行 `docker compose up -d`。
- **详情**：参见 **[部署指南 → 存储拓扑与数据卷挂载](Deployment#存储拓扑与数据卷挂载)**。

## 二、凭据、Cookie 与安全

### 1. 修改管理员密码后，所有设备都需要重新登录吗？
- **原因**：这是会话失效机制。修改密码会使系统内当前所有持久化会话凭据即时作废。
- **结果**：所有已登录设备均需重新输入新密码进行身份验证。

### 2. 加密密钥丢失了该如何恢复？
- **原因**：静态加密使用 AES-256-GCM 算法，缺少密钥时密文无法还原。
- **处理**：重置 `runtime_auth` 凭据，使管理员密码恢复为默认值 `p1a2s3s4` 并重新生成 `auth_secret`；清理旧密文 cookies 与 bot token 后在设置页重新填写。
- **详情**：完整影响评估与恢复命令参见 **[静态加密 → 密钥丢失的恢复](Encryption#密钥丢失的恢复)**。

### 3. 顶栏出现 Cookie / 探活告警？
系统在启动时及每隔 30 分钟后台自动探活凭据：
- **Cookie 已失效**（红条）：会话已过期。在「系统设置 → ExHentai」中重新填入最新凭据并点击「测试登录」。
- **无里站权限**（红条）：账户无 ExHentai 权限或缺少有效 `igneous`。可切换为 `e-hentai.org` 表站域名使用。
- **IP 封禁**（红条）：源站返回 IP 封禁或暂时限制提示，需更换出口节点或等待源站解封，不是缺少 `igneous`。
- **探活失败**（橙条）：网络超时或站点波动，Cookie 未必失效。
红条状态下系统自动暂停云端同步任务，避免影响本地数据。

### 4. 为什么不建议在 `docker-compose.yml` 中配置凭证环境变量？
- **原因**：系统以 PostgreSQL 数据库作为配置项的唯一数据来源。在环境变量中硬编码容易导致环境与库中配置产生分歧。
- **处理**：在 Web 设置界面保存凭据；启用 `ENCRYPTION_KEY` 后敏感字段自动加密落库。

## 三、下载调度与并发控制

### 1. 遇到 ExHentai 302 临时挑战告警并自动全局暂停？
- **原因**：触发源站动态访问频控，系统自动挂起下载队列以降低封禁风险。
- **处理**：后台探针默认每隔 10 分钟自动探活一次；源站解除限制后下载队列自动恢复。

### 2. 官方归档整包下载失败重试或断点续传会重复扣除 GP 吗？
- **原因与机制**：生成官方归档任务后，系统将下载 URL 持久化保存在任务元数据中。常规网络中断续传（HTTP Range）或失败重试会直接复用已保存的 URL，不重复向云端申请打包。
- **例外条件**：若归档文件在云端损坏、下载链接彻底过期失效或用户主动发起重新打包申请，则需重新向源站请求并按源站规则扣减 GP。

### 3. 下载报错 `image download request failed` 如何排查？
- **原因**：网络波动、H@H 节点连接超时或代理中断。系统内置指数退避重试（30 秒至 6 小时）。
- **处理**：
  在宿主机查看错误日志：
  ```bash
  docker logs galleryvault-backend --since 6h | grep -E "download task failed|page download failed"
  ```
  - `ReadTimeout`：节点传输超时，看门狗会自动跳过并在缺少节点 key 时换节点。
  - `ConnectTimeout` / `RemoteProtocolError`：代理链路不稳定，可检查代理出口或调小并发页数 `page_concurrency`。

### 4. 点击了暂停按钮，为什么当前任务还在继续？
- **原因**：点击暂停后，系统停止向任务池派发新页面与新任务。正在传输中的单张图片会在当前生命周期内完成传输并写入磁盘，以保证落盘文件完整。

## 四、库管理、查重与版本追踪

### 1. 从设置中移除了某个库根目录，里面的画廊会从系统消失吗？
- **原因**：移除目录配置仅代表后续扫描跳过该路径。
- **结果**：数据库中已索引的画廊记录与元数据仍会保留。

### 2. 在本地删除了画廊，能否找回？
- **未勾选从磁盘删除**：画廊进入回收站，可在回收站中撤回恢复。
- **勾选从磁盘删除**：先标记进入回收站，磁盘文件全部删除成功后才移除索引记录。删盘失败时保留在回收站。若画廊任一副本路径超出扫描根白名单，则**整本跳过删除**。只读挂载删除失败时保留数据库记录并给出提示。
- **详情**：参见 **[库维护指南 → 回收站与删除保护机制](Manage#回收站与删除保护机制)**。

### 3. 新版本已下载完成，为什么「更新画廊」页面依然显示该条目？
- **原因**：新 GID 画廊下载入库后，需触发检测同步状态。
- **处理**：点击「立即检测」，系统会确认新版本完整存在后安全清理旧版本本地残留；若该条目被标记为「忽略」，则不执行清理。

### 4. 跨 GID 查重的作用与机制是什么？
- **机制**：针对不同汉化组、压制规格或多次上传产生的不同 GID 同源画廊，算法清洗展会前缀、汉化组标签和版本后缀，按核心标题与 `artist` 标签进行相似度聚类打分。
- **操作**：在「管理 → 查重 → 跨GID重复」中对比本地入库版本与云端未入库版本，勾选保留版本后可批量取消云端收藏、删除本地重复副本或标记忽略。

### 5. 归档或下载保存时报「File name too long」/「[Errno 36]」错误如何解决？
- **原因**：Linux 文件系统对单文件名限制为 255 字节。UTF-8 中文/日文字符多占 3 字节，超长文件名加 `.cbz.partial`（12 字节）易触发 `[Errno 36]`。
- **规范**：系统限制基础文件名 ≤ 243 字节，目录名 ≤ 247 字节。格式限制与命名规范参见 **[客户端格式与元数据规范 → CBZ / CBR 归档包与规范](Compatibility#2-cbz--cbr-归档包与规范)**。
- **修复命令**：历史归档文件名对齐使用仓库根脚本（未打入容器镜像）：
  ```bash
  python scripts/repair_cbz_filenames.py --target-dir /path/to/archive --dry-run
  python scripts/repair_cbz_filenames.py --target-dir /path/to/archive
  ```
  完整参数与执行说明参见 **[部署指南 → 运维工具与离线修复脚本速查](Deployment#运维工具与离线修复脚本速查)**。

### 6. 本地画廊或冷库 CBZ 存在前导 GID 冗余污染如何批量清洗与修复？
- **原因**：外部工具导出或迁移产生 `[12345] 12345-标题` 等重复前缀，导致标题与索引识别异常。
- **处理**：使用 `repair_cold_archives.py` 清洗前缀并通过官方 GData 接口重构 `.galleryvault.json` 索引：
  ```bash
  # 演练预览
  docker compose exec backend python /app/galleryvault/scripts/repair_cold_archives.py --archive-dir /archive --dry-run

  # 正式执行
  docker compose exec backend python /app/galleryvault/scripts/repair_cold_archives.py --archive-dir /archive
  ```
  脚本说明与备份恢复入口参见 **[备份与恢复 → 离线全量修复与元数据清洗工具](Backup#离线全量修复与元数据清洗工具)**；完整参数参见 **[部署指南 → 运维工具与离线修复脚本速查](Deployment#运维工具与离线修复脚本速查)**。

### 7. 冷存储多根目录（archive_roots）如何工作？如何安全清理下载源目录？
- **多根存储均衡**：在「设置 → 资料库」中配置多个 `archive_roots` 路径。冷归档时系统通过 `statvfs` 探测可用容量，优先写入空间充裕的磁盘。单卷上限 500 页且 2GiB，超限打成冷目录。
- **清理源目录**：存储面板点击清理按钮（`POST /api/system/purge-archived-sources`）。系统核对冷库完整性，跳过 pending / downloading 任务，仅删除已有完好冷库 CBZ 对应的热目录散图。
- **详情**：配置与卷挂载参见 **[部署指南 → 冷热分层存储、多盘挂载与归档规则](Deployment#2-冷热分层存储多盘挂载与归档规则)**。

### 8. 画廊出现缺页、坏图或打不开如何排查与修复？
- **排查**：进入「管理 → 缺页体检」（`#/integrity`），点击「扫描缺页与坏图」。系统通过二进制文件头（Magic Header，校验 JPEG/PNG/GIF/WebP 签名）和序号连续性检查异常文件。
- **处理**：扫描后标红显示异常项目，点击「修复」或「全选并修复」。系统仅重新下载损坏页与缺失页，完好页面保持原样。

## 五、阅读器、标签与客户端生态

### 1. 为什么有些标签没有中文翻译？
- **原因**：标签翻译来自 EhTagTranslation/Database。未收录的词条显示原始英文。
- **处理**：在「设置 → 标签」点击「立即更新」。更新任务在后台运行，执行进度在「日志」页面查看。

### 2. 阅读器翻页后返回画廊库，此前的搜索条件还会保留吗？
- **表现**：保留。阅读器维护独立的浏览上下文，退出阅读器返回列表时多标签筛选、排序与页码保持不变。

### 3. 如何通过第三方阅读客户端（如 Tachiyomi / Mihon / Panels）访问？
- **处理**：系统提供标准 OPDS 服务：目录为 `GET /api/opds`，条目中的 CBZ 获取链接为 `GET/HEAD /api/galleries/{id}/export.cbz`。两个端点均接受 HTTP Basic 认证，用户名为 `galleryvault`，密码为管理员登录密码；未认证时返回 `401` 并附带 `WWW-Authenticate: Basic` 响应头。

### 4. 将应用「添加到主屏幕」（PWA）是否会将画廊离线下载到本地？
- **表现**：不会。PWA 仅缓存前端界面资源与静态样式，画廊图片与元数据均按需在线流式加载。

### 5. Telegram Bot 能做什么？命令在哪看？
- **配置与能力**：在「设置 → Telegram」配置 token、chat ID 与允许的 user ID。支持粘贴画廊 URL 自动入队、`/queue` 队列管理、`/status` `/storage` `/quota` `/cookie` 探活以及 `/search` `/info` `/random` 本地查询。
- **命令列表**：完整命令对照见 **[系统设置 → Telegram bot 控制命令](Settings#设置settings)**。
